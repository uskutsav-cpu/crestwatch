# Run the matched comparison

1. Open the facilitator tool: https://crestwatch-river-guide.utsavsresearch.chatgpt.site/review . Keep the assessor's scoring guide off the participant's screen.
2. Use consenting adults, anonymous codes and public examples. Capture device, date, prior familiarity, source timestamps, app version and order in the supplied session sheet.
3. Alternate interface order: odd-numbered codes start with CrestWatch; even-numbered codes with NOAA. Use the same three task prompts, same device and a 120-second cap. Start from the loaded Vicksburg view with no threshold answer preselected. Permit relevant help/source links in both interfaces.
4. Stop at completion, give-up or cap. Record the unaided result before help. Write the participant's actual explanation first in the note; then record assistance or interruption. Distinguish incorrect beliefs from unavailable data. Never invent an explanation that was not elicited.
5. Repeat on the other interface without revealing the scored answers in between. This repeated-task design still has learning effects; document them. Use a facilitator other than the developer when possible. An independent scorer can review anonymized explanations with the interface label hidden.
6. Export the original observation CSV after each session. If sessions occur on separate browsers, import their original files locally into one Review Lab. Do not import the same export repeatedly. The report excludes all ambiguous repeats instead of choosing the best attempt; preserve raw files to resolve errors transparently.
7. Export the descriptive report. The first table uses ALL matched participant/task pairs, including incomplete, assisted and misunderstood attempts. Review source interruptions and missing explanations separately.

## Primary comparison
For each task, report counts of:
- Both interfaces completed unaided with a correct explanation.
- CrestWatch only met that standard.
- Official pages only met that standard.
- Neither met that standard.

Report total matched pairs, pairs with any unassessed explanation, unpaired codes, invalid records and excluded duplicates. All six observations are needed for a fully covered participant, but partial sessions remain in the raw data. Do not silently drop participants with unsuccessful tasks. Never pool three task attempts as three independent people.

An unassessed answer does not demonstrate success and does not prove misunderstanding. An assisted answer is retained and does not count as unaided success. Failed navigation and incorrect understanding are distinct; inspect the completion and explanation fields separately.

## Secondary timing
Only correctly completed unaided attempts contribute to successful-task median time. Paired timing requires success on both interfaces for that task. Present it alongside ALL outcome counts. Successful-only timing is selective; it can make a difficult interface look fast by excluding its failures. Do not compare unmatched medians as a treatment effect or present speed as understanding.

## Fair scoring
Use the USER_TESTING.md anchors in the competition kit. Accept the precision actually displayed by each interface (e.g., NOAA 13.58 ft versus CrestWatch 13.6 ft). Require the observation time rather than a page refresh time. If the source changes between conditions, note the timestamp and score against what that participant actually saw. Missing data should not be scored as a participant's incorrect belief.

## Interpreting the result
- More CrestWatch-only than official-only outcomes on a task: descriptive evidence consistent with a benefit on that task in this sample; still limited by design, sample and scoring.
- More official-only than CrestWatch-only: report that unfavorable result and investigate it.
- Similar counts or too few assessed pairs: mixed or insufficient evidence, not an improvement claim.
- Many unassessed, interrupted or ambiguous attempts: improve measurement before drawing conclusions.

A correct explanation while using an interface is not proof of retained learning or changed real-world decisions. A delayed transfer study would be needed for a stronger learning claim. None of these tasks validates property flood prediction.
